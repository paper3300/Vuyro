# 데모 실행 안내

> 직접 데모를 돌려 보는 절차다. 명령은 Windows PowerShell 기준이고, 저장소 폴더(`D:\Git\Vuyro` 같은 곳)에서 실행한다.
> 점검 결과는 [[데모 점검 결과]]에 있다.

## 1. 준비 (한 번)

- Node 24.16 이상(24.x), git, pnpm 10(`npm i -g pnpm@10.34.7`)
- 실제 에이전트로 돌릴 때만: Claude Code CLI 또는 Codex CLI를 설치하고 로그인해 둔다.

```powershell
pnpm install
pnpm -r build
# 이 창에서 쓸 vuyro 명령
function vuyro { node "$PWD\packages\cli\dist\bin.js" @args }
```

## 2. 샘플 저장소 만들기

에이전트가 일할 작은 메모장 저장소를 **이 저장소 밖** 빈 폴더에 만든다(git init과 첫 커밋까지 한다).

```powershell
node tools\demo\scripts\create-sample.ts D:\demo\notepad
```

## 3. 앱 실행

토큰을 쓰지 않는 **체험 모드**(대본 에이전트가 Spec·Plan·Dev·QA를 대신한다. Dev는 샘플 저장소의 파일을 실제로 고친다):

```powershell
$env:VUYRO_DATA_DIR = "$env:TEMP\vuyro-demo"          # 데모용 데이터 폴더
$env:VUYRO_ENGINE_ENTRY = "$PWD\apps\desktop\scripts\dev-engine.ts"
pnpm --filter @vuyro/desktop start
```

- 실제 에이전트로 돌리려면 `VUYRO_ENGINE_ENTRY`를 지우고 띄운다(`Remove-Item Env:VUYRO_ENGINE_ENTRY`). 기본 템플릿의 에이전트 노드는 Claude를 기본 모델로 부른다. 작은 모델을 쓰려면 아래 6번처럼 템플릿을 내보내 노드 `params`에 `"provider"`·`"model"`을 넣고 가져온다.
- 설치본으로 보려면: `pnpm --filter @vuyro/desktop package:dir` → `apps\desktop\release\win-unpacked\Vuyro.exe`(Node가 함께 들어 있다).

## 4. 프로젝트와 폴더

1. 앱 첫 화면에서 프로젝트 이름(예: `notepad`)을 넣고 **프로젝트 만들기**.
2. 프로젝트 폴더는 CLI로 지정한다(앱에는 아직 이 설정이 없다, D-072). 같은 데이터 폴더를 쓰도록 같은 창에서:

```powershell
vuyro auth login        # 화면에 뜬 확인 창의 코드가 같으면 [예]
$env:VUYRO_HUMAN_CREDENTIAL = "<출력된 vhc_… 값>"
vuyro project list      # 프로젝트 id 확인
vuyro project configure <프로젝트 id> --root D:\demo\notepad
```

엔진이 다시 시작되면 `vuyro auth login`을 다시 한다(자격은 엔진 메모리에만 있다).

## 5. 기본 템플릿 티켓 하나 (승인 게이트까지)

1. **보드** → **+ 새 티켓** → 제목(예: "메모 목록 정렬") → 템플릿 **AI-Native SDLC** → **티켓 만들기**.
2. 카드를 눌러 상세를 연다. BrainStorming 칸에 요점을 적고 **완료**.
3. Spec이 끝나면 **Spec approval**이 사람 차례다. 의견을 적고 **반려**하면 Spec이 다시 돌고(반려 루프), **승인**하면 Plan → 병렬 Dev 2레인 → Join → QA로 간다.
   - Dev 두 레인이 같은 `src/app.js`를 잡으므로 한 레인은 내부 체크아웃을 기다렸다가 이어서 한다. `vuyro workspace show --project <id> --all`에서 대기 기록을 볼 수 있다.
4. QA가 끝나면 다시 사람 차례다. **승인** → Done.
5. **그래프로 보기**: 노드 상태, 병렬 레인 수, 되돌아가는 간선 라벨. 노드를 누르면 시간·토큰·도구 호출과 에이전트 로그가 나온다. `vuyro ticket stats <티켓 id>`와 수치가 같다.

## 6. JSON 내보내기 / 가져오기

1. **템플릿** 탭 → **AI-Native SDLC** → **JSON으로 내보내기** → (노드 타입을 함께 넣을지 고르고) **내보낼 내용 만들기** → **클립보드에 복사**(또는 파일로 저장).
2. **JSON 가져오기…** → 붙여 넣기(또는 파일 열기) → **미리보기**.
3. 템플릿 칸에서 **새 id로**를 고르고 id(예: `myteam/ai-sdlc-copy`)와 이름을 적은 뒤 **적용**. 같은 노드 타입은 "이미 있음"으로 건너뛴다.
4. 실행 내용을 읽고 맨 아래 확인을 체크 → **가져오기**. 새 티켓을 만들 때 그 템플릿 카드가 보인다.

## 7. 공유 노드 (여러 티켓을 한 번에 빌드)

아래 두 파일을 저장소 밖 아무 곳에 만든다.

`build-node.json`:

```json
{
  "name": "build",
  "label": "Notepad build",
  "node": { "type": "vuyro.script", "version": 1, "params": { "program": "node", "args": ["scripts/build.mjs"] } },
  "batchTrigger": { "count": 3 },
  "maxConcurrent": 1,
  "protect": [{ "path": "src/**", "mode": "shared" }],
  "onBatchFailure": "blame"
}
```

`build-flow.json`: Task(사람) → Dev(에이전트) → Build(공유 노드 요청) → Done, 빌드 실패는 Dev로 되돌아간다.

```json
{
  "vuyro": "export", "formatVersion": 1, "kind": "template", "id": "myteam/notepad-build", "version": 1, "name": "Notepad build flow",
  "content": {
    "id": "myteam/notepad-build", "version": 1, "name": "Notepad build flow",
    "nodes": [
      { "id": "task", "type": "vuyro.human-task", "version": 1, "label": "Task", "params": { "instructions": "Describe the change." } },
      { "id": "dev", "type": "vuyro.agent", "version": 1, "label": "Dev", "params": { "instructions": "Make the change in src/ and finish on 'done'." } },
      { "id": "build", "type": "vuyro.shared-request", "version": 1, "label": "Build", "params": { "sharedNode": "build" } },
      { "id": "end", "type": "vuyro.end", "version": 1, "label": "Done" }
    ],
    "edges": [
      { "from": { "node": "task", "port": "done" }, "to": { "node": "dev", "port": "in" } },
      { "from": { "node": "dev", "port": "done" }, "to": { "node": "build", "port": "in" } },
      { "from": { "node": "build", "port": "done" }, "to": { "node": "end", "port": "in" } },
      { "from": { "node": "build", "port": "error" }, "to": { "node": "dev", "port": "in" }, "label": "fix the build" }
    ]
  }
}
```

```powershell
vuyro definition save "@build-flow.json"
vuyro shared define --project <프로젝트 id> "@build-node.json"
```

티켓 세 개를 앱(템플릿 **Notepad build flow**)이나 CLI로 만들고 Task를 끝낸다. 체험 모드에서 제목에 `[broken]`을 넣은 티켓은 첫 Dev 실행이 문법 오류를 남긴다.

```powershell
vuyro ticket create --project <id> --template myteam/notepad-build --title "빌드 B [broken]"
vuyro node done --ticket <티켓 id> --node task --port done --summary "B"
vuyro shared show --project <id> build
```

세 요청이 모이면 묶음이 한 번 돈다. 실패하면 오류 줄(`src/…js:2: error: …`)의 파일을 고친 티켓만 Dev로 돌아가고, 나머지는 대기열에 남는다. 공유 노드는 Blocked가 되었다가 원인 티켓이 고쳐지면 풀려서 다시 빌드한다. 보드 위의 공유 노드 카드에서도 보인다.

## 8. worktree 모드 (선택)

기본 템플릿은 `shared`로 고정돼 있다(D-073). 6번처럼 내보낸 JSON의 `content.settings`를 `{"workspaceMode": "worktree"}`로 바꾸고 새 id로 가져와 티켓을 만든다. Dev 레인마다 `<데이터 폴더>\wt\…`에 worktree가 생기고, Join이 레인 브랜치를 티켓 브랜치 `vuyro/<티켓>/ticket`에 머지한다. 원본 저장소의 브랜치와 작업 폴더는 건드리지 않는다. 티켓이 끝나면 worktree는 지워지고 티켓 브랜치는 남는다.

## 9. 트레이

1. 에이전트가 도는 동안 창의 ✕를 누른다. 창은 닫히고 알림 영역에 Vuyro 아이콘이 남는다(처음 한 번 알림). 툴팁에 실행 중 작업 수가 보인다.
2. 잠시 뒤 아이콘을 누르거나(또는 앱을 다시 실행) 창을 연다. 닫혀 있던 동안 진행된 상태가 그대로 보인다.
3. 아이콘 오른쪽 클릭 → **완전 종료**. 실행 중인 작업이 있으면 확인을 묻는다. [취소]하면 그대로 돌고, 확인하면 앱과 엔진이 함께 멈춘다. 멈춘 에이전트는 다음 시작 때 다시 줄을 선다.

## 정리

- 데모 데이터는 `VUYRO_DATA_DIR` 폴더에 있다. 지워도 샘플 저장소는 그대로다.
- 샘플 저장소에는 에이전트가 고친 파일과 `vuyro/…` 티켓 브랜치가 남는다. 필요 없으면 그 저장소에서 직접 정리한다.
