# 데모 실행 안내

> 직접 데모를 돌려 보는 절차다. 명령은 Windows PowerShell 기준이다. 깨끗한 PC에서 처음부터 끝까지 따라 할 수 있게 썼다.
> 점검 결과는 [[데모 점검 결과]]에 있다.

**자리표시자** (자기 PC의 경로로 바꿔 쓴다. 공백이 있으면 따옴표로 감싼다)

| 표기 | 뜻 |
|---|---|
| `<저장소 폴더>` | Vuyro 저장소를 받은 폴더 |
| `<샘플 저장소 폴더>` | 에이전트가 일할 메모장 저장소. **Vuyro 저장소 밖**의 아직 없거나 빈 폴더 |
| `<JSON 폴더>` | 7번의 JSON 두 파일을 둘 폴더(저장소 밖 아무 곳) |

## 1. 준비 (한 번)

- Node 24.16 이상(24.x), git, pnpm 10(`npm i -g pnpm@10.34.7`)
- 실제 에이전트로 돌릴 때만: Claude Code CLI 또는 Codex CLI를 설치하고 로그인해 둔다.

```powershell
cd <저장소 폴더>
pnpm install
pnpm -r build
```

## 2. 샘플 저장소 만들기

에이전트가 일할 작은 메모장 저장소를 만든다(git init과 첫 커밋까지 한다).

```powershell
cd <저장소 폴더>
node tools\demo\scripts\create-sample.ts <샘플 저장소 폴더>
```

## 3. 앱 실행 (터미널 1)

PowerShell 창 하나를 연다. 이 창은 앱이 떠 있는 동안 앱이 차지한다(창을 ✕로 닫아도 앱은 트레이에 남으므로 계속 차지한다). CLI는 4번처럼 **다른 창**에서 쓴다.

토큰을 쓰지 않는 **체험 모드**(대본 에이전트가 Spec·Plan·Dev·QA를 대신한다. Dev는 샘플 저장소의 파일을 실제로 고친다):

```powershell
cd <저장소 폴더>
$env:VUYRO_DATA_DIR = "$env:TEMP\vuyro-demo"          # 데모용 데이터 폴더(터미널 2도 같은 값)
$env:VUYRO_ENGINE_ENTRY = "$PWD\apps\desktop\scripts\dev-engine.ts"
pnpm --filter @vuyro/desktop start
```

- 실제 에이전트로 돌리려면 `VUYRO_ENGINE_ENTRY`를 지우고 띄운다(`Remove-Item Env:VUYRO_ENGINE_ENTRY`). 기본 템플릿의 에이전트 노드는 Claude를 기본 모델로 부른다. 작은 모델을 쓰려면 6번처럼 템플릿을 내보내 노드 `params`에 `"provider"`·`"model"`을 넣고 가져온다.
- 설치본으로 보려면: `pnpm --filter @vuyro/desktop package:dir` → `apps\desktop\release\win-unpacked\Vuyro.exe`(Node가 함께 들어 있다). 설치본은 기본 데이터 폴더(`%LOCALAPPDATA%\Vuyro`)를 쓴다. 터미널 2에서는 `VUYRO_DATA_DIR`를 정하지 않는다.

## 4. CLI 준비 (터미널 2)

PowerShell 창을 하나 더 연다. 앱과 **같은 데이터 폴더**를 가리켜야 같은 엔진에 붙는다.

```powershell
cd <저장소 폴더>
$env:VUYRO_DATA_DIR = "$env:TEMP\vuyro-demo"          # 터미널 1과 같은 값
$VuyroCli = "$PWD\packages\cli\dist\bin.js"
function vuyro { node $VuyroCli @args }                 # 다른 폴더로 옮겨 가도 쓸 수 있다
vuyro auth login        # 화면에 뜬 확인 창의 코드가 터미널과 같으면 [예]
$env:VUYRO_HUMAN_CREDENTIAL = "<출력된 vhc_… 값>"   # 출력의 PowerShell: 줄을 그대로 붙여 넣어도 된다
vuyro project list
```

- 엔진이 다시 시작되면(완전 종료 후 다시 실행 등) `vuyro auth login`을 다시 한다(자격은 엔진 메모리에만 있다).
- 읽기만 하는 명령(`project list`, `ticket show`, `ticket stats`, `workspace show`, `shared show`)은 로그인 없이도 된다.

## 5. 프로젝트와 기본 템플릿 티켓 (승인 게이트까지)

1. 앱 첫 화면 **새 프로젝트**에서 이름(예: `notepad`)을 넣고 **폴더 고르기…** → `<샘플 저장소 폴더>`를 고른다. 경로 옆에 **git 저장소**가 보인다.
2. **작업 공간 모드**는 **공유 폴더 (shared)** 그대로 두고 **프로젝트 만들기**. (git 저장소가 아닌 폴더면 worktree는 고를 수 없다.)
   - 폴더와 모드는 나중에 위쪽의 **프로젝트 설정**에서 바꿀 수 있다. 새 티켓부터 적용된다.
3. **보드** → **+ 새 티켓** → 제목(예: "메모 목록 정렬") → 템플릿 **AI-Native SDLC** → **티켓 만들기**.
4. 카드를 눌러 상세를 연다. BrainStorming 칸에 요점을 적고 **완료**.
5. Spec이 끝나면 **Spec approval**이 사람 차례다. 의견을 적고 **반려**하면 Spec이 다시 돌고(반려 루프), **승인**하면 Plan → 병렬 Dev 2레인 → Join → QA로 간다.
   - Dev 두 레인이 같은 `src/app.js`를 잡으므로 한 레인은 내부 체크아웃을 기다렸다가 이어서 한다. 터미널 2의 `vuyro workspace show --project <프로젝트 id> --all`에서 대기 기록을 볼 수 있다.
6. QA가 끝나면 다시 사람 차례다. **승인** → Done. `<샘플 저장소 폴더>\src\app.js`에 두 레인의 수정이 모두 있다.
7. **그래프로 보기**: 노드 상태, 병렬 레인 수, 되돌아가는 간선 라벨. 노드를 누르면 시간·토큰·도구 호출과 에이전트 로그가 나온다. 터미널 2의 `vuyro ticket stats <티켓 id>`와 수치가 같다(티켓 id는 `vuyro ticket list --project <프로젝트 id>`).

## 6. JSON 내보내기 / 가져오기

1. **템플릿** 탭 → **AI-Native SDLC** → **JSON으로 내보내기** → (노드 타입을 함께 넣을지 고르고) **내보낼 내용 만들기** → **클립보드에 복사**(또는 파일로 저장).
2. **JSON 가져오기…** → 붙여 넣기(또는 파일 열기) → **미리보기**.
3. 템플릿 칸에서 **새 id로**를 고르고 id(예: `myteam/ai-sdlc-copy`)와 이름을 적은 뒤 **적용**. 같은 노드 타입은 "이미 있음"으로 건너뛴다.
4. 실행 내용을 읽고 맨 아래 확인을 체크 → **가져오기**. 새 티켓을 만들 때 그 템플릿 카드가 보인다.

## 7. 공유 노드 (여러 티켓을 한 번에 빌드)

공유 노드는 shared 모드 프로젝트에서만 쓴다(D-051). 아래 두 파일을 `<JSON 폴더>`에 UTF-8로 만든다(메모장으로 저장해도 된다).

`build-node.json`:

```json
{
  "name": "build",
  "label": "Notepad build",
  "node": { "type": "vuyro.script", "version": 1, "params": { "program": "node", "args": ["scripts/build.mjs"] } },
  "batchTrigger": { "count": 3 },
  "maxConcurrent": 1,
  "protect": [{ "path": "src/**", "mode": "shared" }],
  "onBatchFailure": "blame"
}
```

`build-flow.json`: Task(사람) → Dev(에이전트) → Build(공유 노드 요청) → Done, 빌드 실패는 Dev로 되돌아간다.

```json
{
  "vuyro": "export", "formatVersion": 1, "kind": "template", "id": "myteam/notepad-build", "version": 1, "name": "Notepad build flow",
  "content": {
    "id": "myteam/notepad-build", "version": 1, "name": "Notepad build flow",
    "nodes": [
      { "id": "task", "type": "vuyro.human-task", "version": 1, "label": "Task", "params": { "instructions": "Describe the change." } },
      { "id": "dev", "type": "vuyro.agent", "version": 1, "label": "Dev", "params": { "instructions": "Make the change in src/ and finish on 'done'." } },
      { "id": "build", "type": "vuyro.shared-request", "version": 1, "label": "Build", "params": { "sharedNode": "build" } },
      { "id": "end", "type": "vuyro.end", "version": 1, "label": "Done" }
    ],
    "edges": [
      { "from": { "node": "task", "port": "done" }, "to": { "node": "dev", "port": "in" } },
      { "from": { "node": "dev", "port": "done" }, "to": { "node": "build", "port": "in" } },
      { "from": { "node": "build", "port": "done" }, "to": { "node": "end", "port": "in" } },
      { "from": { "node": "build", "port": "error" }, "to": { "node": "dev", "port": "in" }, "label": "fix the build" }
    ]
  }
}
```

터미널 2에서 그 폴더로 옮겨 가 저장한다(`@파일`은 현재 폴더에서 찾는다).

```powershell
cd <JSON 폴더>
vuyro definition save "@build-flow.json"
vuyro shared define --project <프로젝트 id> "@build-node.json"
```

티켓 세 개를 앱(템플릿 **Notepad build flow**)이나 CLI로 만들고 Task를 끝낸다. 체험 모드에서 제목에 `[broken]`을 넣은 티켓은 첫 Dev 실행이 문법 오류를 남긴다.

```powershell
vuyro ticket create --project <프로젝트 id> --template myteam/notepad-build --title "빌드 A"
vuyro ticket create --project <프로젝트 id> --template myteam/notepad-build --title "빌드 B [broken]"
vuyro ticket create --project <프로젝트 id> --template myteam/notepad-build --title "빌드 C"
vuyro node done --ticket <티켓 id> --node task --port done --summary "A"     # 세 티켓 모두
vuyro shared show --project <프로젝트 id> build
```

세 요청이 모이면 묶음이 한 번 돈다. 실패하면 오류 줄(`src/…js:2: error: …`)의 파일을 고친 티켓만 Dev로 돌아가고, 나머지는 대기열에 남는다. 공유 노드는 Blocked가 되었다가 원인 티켓이 고쳐지면 풀려서 다시 빌드한다. 보드 위의 공유 노드 카드에서도 보인다.

## 8. worktree 모드

1. 위쪽 **프로젝트 설정** → **작업 공간 모드**에서 **git worktree**를 고르고 **저장**. (프로젝트 폴더가 git 저장소일 때만 고를 수 있다.)
2. 기본 템플릿(**AI-Native SDLC**)으로 새 티켓을 만들고 5번처럼 진행한다. 기본 템플릿은 모드를 정하지 않으므로 프로젝트 설정을 따른다(D-073). 이미 만든 티켓은 만들 때의 설정 그대로 돈다.
3. Dev 레인마다 `<데이터 폴더>\wt\…`에 worktree가 생기고, Join이 레인 브랜치를 티켓 브랜치 `vuyro/<티켓>/ticket`에 머지한다. 원본 저장소의 브랜치와 작업 폴더는 건드리지 않는다. 티켓이 끝나면 worktree는 지워지고 티켓 브랜치는 남는다(`git -C <샘플 저장소 폴더> branch`).
4. 공유 노드(7번)를 다시 쓰려면 모드를 **공유 폴더**로 되돌린다.

## 9. 트레이와 완전 종료 (사람이 확인)

1. 에이전트가 도는 동안 창의 ✕를 누른다. 창은 닫히고 알림 영역에 Vuyro 아이콘이 남는다(처음 한 번 알림). 툴팁에 실행 중 작업 수가 보인다.
2. 잠시 뒤 아이콘을 누르거나(또는 앱을 다시 실행) 창을 연다. 닫혀 있던 동안 진행된 상태가 그대로 보인다.
3. **완전 종료 확인** — 실행 중인 작업이 있을 때(예: Spec 승인 직후) 한다.
   1. 아이콘 오른쪽 클릭 → **완전 종료** → "실행 중인 작업 N개가 있습니다…" 확인 창이 뜬다. **[취소]** → 창과 트레이 아이콘이 그대로 있고 작업이 계속 진행된다(툴팁의 수가 바뀐다).
   2. 다시 **완전 종료** → **[종료]** → 트레이 아이콘이 사라지고 터미널 1의 `pnpm … start`가 끝난다.
   3. 터미널 2에서 `vuyro engine status` → `the engine is not reachable`(종료 코드 3)이 나온다. 몇 초 뒤 다시 해도 같다(앱이 엔진을 다시 띄우지 않는다).
   4. 터미널 1에서 앱을 다시 띄운다. 멈췄던 에이전트 노드가 다시 줄을 서서 이어서 돈다. 터미널 2는 `vuyro auth login`을 다시 한다.

## 정리

- 데모 데이터는 `VUYRO_DATA_DIR` 폴더(`$env:TEMP\vuyro-demo`)에 있다. 지워도 샘플 저장소는 그대로다.
- 샘플 저장소에는 에이전트가 고친 파일과 `vuyro/…` 티켓 브랜치가 남는다. 필요 없으면 그 저장소에서 직접 정리한다.
