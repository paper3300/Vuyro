# 데모 점검 결과

> [[PRD]] MVP 11개 항목을 샘플 저장소(이 저장소 밖, `tools/demo`로 만든 메모장)와 실제 앱·CLI로 하나씩 확인한 결과다.
> 실제 모델 호출(Claude haiku, Codex luna)은 M7a에서 했다([[초기 검증 결과]] "M7a"). M7b는 앱(개발용 엔진의 대본 에이전트)과 CLI, 실제 git·실제 빌드 스크립트로 확인했다. 토큰은 쓰지 않았다.
> 직접 돌려 보는 절차는 [[데모 실행 안내]]에 있다.

## 이번에 고친 것

1. **가져오기가 BOM이 붙은 JSON을 거부했다.** Windows 도구가 흔히 붙이는 BOM을 무시한다. 시험: `exchange.test.ts`.
2. **샘플 빌드가 공유 노드의 원인 추정에 맞지 않았다.** 문법 검사 후 `file:line: error: message`로 출력한다. 시험: `tools/demo` 빌드 시험.
3. **개발용 엔진의 Dev가 파일을 고치지 않아** 체크아웃·worktree·공유 빌드를 앱에서 볼 수 없었다. 대본 Dev가 작업 폴더의 파일을 체크아웃하고 고친다.
4. **데스크톱 통합 시험이 엔진 프로세스를 남겼다**(전체 병렬 실행에서 한 번). 시험이 띄운 엔진을 모두 기억했다가 정리 때 끝낸다.
5. **프로젝트 폴더가 없으면 에이전트가 엔진을 띄운 프로세스의 현재 폴더에서 일했다**(앱 설치 폴더 등, 수정 권한까지 있음). 데이터 폴더의 티켓별 빈 폴더(`work/<티켓 키>`)에서 일한다(d983e37, D-072). 시험: `daemon-views.test.ts`.
