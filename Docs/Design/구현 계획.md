# 구현 계획 (데모까지)

> 데모 = [[PRD]] MVP 목록 전체. 기술 스택은 [[기술 스택 결정]]을 따른다.
> 이 문서는 마일스톤 순서, 각 마일스톤의 완료 기준, 진행 상태를 기록한다. 새로 들어온 에이전트는 이 문서와 `git log`로 이어받는다.

## 역할과 진행 방식

| 역할 | 담당 | 하는 일 |
|---|---|---|
| 조율자 | Claude (조율 세션) | 마일스톤 분배, 진행 상태 기록, 에이전트 교체 |
| 구현자 | Claude (claude-opus-5-5, effort high) | 코드 구현, 테스트, 커밋 |
| 검수자 | Codex (gpt-6-sol) | 계획·설계 토론, 마일스톤 diff 리뷰 |

- 마일스톤 하나 = 구현 → 로컬 커밋 → 검수 → 수정 → push.
- 검수 지적 중 기술 판단이 갈리면 구현자와 검수자가 논의해 정하고, 큰 결정은 `Docs/Design/`에 기록한다.
- 기획 질문은 기본값으로 진행하고 [[결정 대기]]에 쓴다.
- 에이전트 맥락이 커지면 세션을 닫고 새로 띄운다. 이어받을 정보는 이 문서의 "진행 상태"와 "인계 메모"에 남긴다.

## 마일스톤

### M0. 저장소 뼈대와 초기 검증

- pnpm workspaces, strict TypeScript, Vitest, ESLint(import 방향 규칙: contracts → engine → 호스트).
- 패키지 골격: `packages/contracts`, `packages/engine`, `packages/agent-adapters`, `packages/cli`, `apps/desktop`(빈 셸). `plugin-sdk`, `mcp`는 MVP 이후라 만들지 않는다.
- [[기술 스택 결정]] §13 검증 중 엔진 바닥에 해당하는 것:
  - #1 named pipe 현재 사용자 전용 보안 설정
  - #5 worker 안 `node:sqlite` WAL과 동시 읽기
- 결과는 `Docs/Design/초기 검증 결과.md`에 기록한다.
- **완료 기준:** `pnpm install && pnpm -r build && pnpm -r test && pnpm lint`가 통과하고, #1·#5 검증 결과(타 계정 차단 여부 또는 확인한 ACL, WAL·동시 읽기 측정)가 문서에 있다.

### M0b. 에이전트 CLI 실제 동작 검증

- 이벤트 계약(M1)을 확정하기 전에 실제 출력과 훅 동작을 확인한다(§13 #2, #3, #4).
- 가장 작은 모델로 Claude `stream-json`, Codex `exec --json` 출력을 녹화해 버전 표시한 픽스처로 저장한다(세션 id, 토큰·비용 필드, 도구 호출, 최종 정착).
- Claude `--settings` PreToolUse 훅 주입과 Codex `hooks.PreToolUse`가 Windows에서 파일 수정을 실제로 막는지 확인한다.
- **완료 기준:** 픽스처가 저장소에 있고, 결과가 `Docs/Design/초기 검증 결과.md`에 있다.

### M1. 계약, 이벤트 저장소, 명령 버스

- `contracts`: 명령·이벤트·봉투·노드 선언 타입과 JSON Schema(Ajv 2020-12, 원격 `$ref` 금지).
- 이벤트 로그(append-only, aggregate id/revision, 전역 sequence, 스키마 버전, 주체)와 같은 트랜잭션 안의 조회 테이블. 재생으로 조회 테이블 재구축.
- 명령 버스: 요청 id 멱등, 기대 revision, 호출자 맥락(주체·티켓·노드·실행 토큰).
- 최소 권한 경계: 실행 토큰의 티켓·노드 범위 검사, AI 주체의 권한 규칙 수정(`permission.edit`)은 항상 거부. 전체 권한 정책과 UI는 MVP 이후.
- **결정 항목(M1에서 계약, M3에서 구현): 사람 UI 자격과 에이전트 자격 분리.**
  - 엔진 토큰 파일은 같은 사용자의 모든 프로세스가 읽을 수 있다. 에이전트 CLI도 마찬가지다. 그래서 파이프 인증만으로는 "사람의 UI"와 "에이전트"를 구분할 수 없다.
  - 후보: 사람 UI용 자격은 파일에 두지 않고, Electron main이 엔진을 띄울 때 상속 핸들이나 stdin으로만 넘긴다. 에이전트는 노드 실행 토큰(환경 변수)으로만 식별하고, 그 범위 밖의 명령은 거부한다.
  - 명령 버스는 연결 인증과 별도로 명령마다 주체를 판정한다.
- 가상 시계, 가짜 파일 시스템·프로세스 주입점.
- **완료 기준:** 명령 → 이벤트 → 조회 테이블, 크래시 후 재생, 멱등·revision 충돌, 토큰 범위 밖 명령 거부 테스트 통과.

### M2. 워크플로 엔진

- 선언형 노드 타입(JSON)과 내장 실행기: 에이전트, 스크립트, 사람 승인, 합류.
- 노드 간 인계 봉투, 경로 표현식(`{{ input.x }}`, `{{ nodes.<id>... }}`)과 조건 JSON AST([[n8n 노드 데이터 전달 분석]] §6).
- 티켓: 템플릿 버전·해시 고정, 노드 상태(Wait/Running/Review/Done/Failed/Rejected/Paused/Queued. Stale은 상태값만 정의).
- 팬아웃·합류, 승인 게이트, QA 반려 루프.
- 기본 템플릿 "AI-Native SDLC"(BrainStorming → Spec → Plan → 병렬 Dev → QA → Done).
- 정의 파일 저장(JSON 정본, 임시 파일 → 교체 → DB 활성 등록 → 시작 시 복구).
- **완료 기준:** 가짜 어댑터로 기본 템플릿 티켓이 Done까지 가는 테스트. Plan의 여러 아이템이 병렬 Dev로 퍼지고, QA가 지정한 아이템만 lineage와 결과 포트로 반려·재실행되는 것을 포함한다.

### M3. 에이전트 어댑터, 엔진 데몬, `vuyro` CLI

- Claude(`stream-json`)와 Codex(`exec --json`) 어댑터: 메시지·도구 호출·사용량·세션 id·결과·정착 상태로 정규화. 모르는 이벤트는 원본 보존.
- §13 #3, #4: 가장 작은 모델로 실제 출력을 녹화해 픽스처로 쓰고 계약 테스트.
- 엔진 상주 프로세스: named pipe JSON-RPC, 이벤트 구독(sequence 이어받기), 단일 인스턴스 잠금.
- `vuyro` CLI: 티켓·노드 명령, `vuyro artifact add`, `vuyro node done`. 노드 에이전트는 환경 변수 실행 토큰으로 식별.
- 산출물 레지스트리(경로 + 버전). 노드별 시간·토큰(입력/캐시/출력)·도구 호출 집계, 티켓 전체 시간과 사람 대기 시간(이벤트에서 계산).
- **완료 기준:** M0b 픽스처로 공급자별 계약 테스트(세션 id, 토큰·비용, 도구 호출, 정착 판정) 통과. CLI로 티켓을 만들고 가짜 어댑터 에이전트가 `vuyro artifact add`, `vuyro node done`으로 노드를 끝내는 통합 테스트.

### M4. 작업 공간과 내부 체크아웃

- 작업 공간 모드 `shared` / `worktree`(사용자 선택).
- 내부 체크아웃 장부(외부 툴 잠금 금지), 자동 체크아웃 훅(옵션): Claude `--settings` PreToolUse, Codex `hooks.PreToolUse`(§13 #2).
- 파일 변경 감지: 감시 + 읽기 전용 git 조회로 후보 → SHA-256. 귀속 불명 변경 표시.
- **완료 기준:**
  - 두 노드가 같은 파일을 잡으려 할 때 충돌 정책대로 막히거나 대기한다.
  - 수정 직전 훅 차단, 훅을 거친 수정, 훅을 우회한 변경(사후 검출 표시)이 각각 테스트된다.
  - worktree 모드: 생성, 노드 실행, 합류 시 머지와 충돌 정책, 정리까지 테스트된다.

### M5. 공유 노드

- 티켓 쪽 공유 노드 요청 노드 타입, 프로젝트 범위 대기열, 실행 조건, 실행 중 소스 보호(읽기 claim), 실패 원인 티켓 추정, 결과를 티켓별 봉투로 나눠 돌려주기.
- **완료 기준:** 티켓 3개가 대기열에 들어와 한 번에 빌드된다. 실패 시 원인 티켓은 오류 포트로 돌아가고 공유 노드는 Blocked가 되며, 나머지 티켓은 대기열에 남았다가 원인 수정 후 함께 재실행되는 테스트.

### M6. 데스크톱 앱

- Electron main(엔진 데몬 연결·기동, 트레이 상주, 완전 종료 확인), preload(contextIsolation), React + Vite UI.
- 화면: 칸반 보드, 그래프 캔버스(@xyflow/react), 노드 상세(시간·토큰·도구 호출, 로그), 티켓 전체 시간·사람 대기 시간·병목 노드, 승인/반려, 티켓 생성.
- 템플릿·노드 타입 JSON 가져오기/내보내기(봉투 형식, 비밀값 제외, 가져올 때 의존성·충돌·실행 내용 미리보기).
- UX 방향은 [[에이전트 패널 시안]](01 · 02 · 07).
- **완료 기준:** 가져온 템플릿으로 앱에서 티켓을 만들고 승인 게이트를 통과시킨다. 창을 닫고 다시 열어도 실행이 계속되고 이벤트 구독이 이어진다.

### M7. 데모

- 이 저장소 밖에 샘플 git 저장소(메모장 같은 작은 앱)를 만든다.
- 실제 Claude/Codex(가장 작은 모델)로 기본 템플릿 티켓 하나를 끝까지 돌리는 스모크.
- MVP 전체 점검표: 공유 노드, 두 작업 공간 모드, 내부 체크아웃, JSON 왕복, 트레이 상주, 시간·토큰 표시.
- 데모 진행 문서와 [[결정 대기]] 정리.

## 인계 메모

(세션을 교체할 때 다음 에이전트가 알아야 할 것을 적는다.)

**M0·M0b → M1 (2026-10-24, 구현자 Claude)**

1. **구조:** `packages/{contracts,agent-adapters,engine,cli}`, `apps/desktop`, `tools/repo-checks`(import 경계 규칙 테스트).
   - import 방향: contracts → agent-adapters → engine → cli·desktop. contracts는 Node 내장 모듈을 못 쓰고, Electron은 desktop만 쓴다.
   - 소스의 import는 `.ts` 확장자로 쓴다. Node 24가 소스를 그대로 실행한다.
2. **명령:** `pnpm install && pnpm -r build && pnpm -r test && pnpm lint`(lint = ESLint + 패키지별 tsc).
   - pnpm 10.34.7은 `npm i -g pnpm@10.34.7`로 `%APPDATA%\npm`에 설치했다. Git Bash에서는 `export PATH="/c/Users/<user>/AppData/Roaming/npm:$PATH"`가 필요하다.
   - 다른 패키지의 테스트는 그 패키지의 `dist`를 쓴다. 그래서 build를 먼저 돌린다.
3. **DB:** `SqliteWorker.open({ path, readOnly? })`로 연다. 연결 하나가 worker 하나다.
   - 쓰기 worker 1개(WAL, `synchronous=FULL`) + 읽기 전용 worker로 나눠 쓴다.
   - 메서드는 `exec`/`run`/`all`/`get`/`transaction([...])`이다. `transaction`은 `BEGIN IMMEDIATE`로 열고, 오류가 나면 롤백한다.
   - 근거와 수치: [[초기 검증 결과]] #5.
4. **IPC:**
   - 서버: `startEnginePipe(pipePath, onConnection, { tokenPath? })`. 토큰 파일 생성·ACL 확인을 마친 뒤에만 리스닝한다.
   - 클라이언트: `readEngineToken()` → `connectAuthenticatedPipe(path, secret)`. 반환된 소켓은 멈춘 상태로 오고, 그 위에 JSON-RPC(NDJSON)를 얹는다.
   - 연결 인증은 "현재 사용자"까지만 보장한다. 사람/에이전트 구분과 AI 권한은 M1 명령 버스에서 명령마다 판정해야 한다(위 M1 결정 항목).
5. **픽스처:** `packages/agent-adapters/fixtures/<provider>/<cli-version>/`. 녹화 명령과 규칙은 같은 폴더의 `README.md`에 있다.
   - 새로 녹화하면 반드시 `node packages/agent-adapters/scripts/sanitize-fixture.ts --root <녹화 폴더> <원본> <픽스처>`로 치환한다. 사용자명과 그 4자 이상 접두사까지 바꾼다.
   - `test/fixtures.test.ts`가 남은 사용자명을 검사한다.
