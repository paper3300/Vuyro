# 구현 계획 (데모까지)

> 데모 = [[PRD]] MVP 목록 전체. 기술 스택은 [[기술 스택 결정]]을 따른다.
> 이 문서는 마일스톤 순서, 각 마일스톤의 완료 기준, 진행 상태를 기록한다. 새로 들어온 에이전트는 이 문서와 `git log`로 이어받는다.

## 역할과 진행 방식

| 역할 | 담당 | 하는 일 |
|---|---|---|
| 조율자 | Claude (조율 세션) | 마일스톤 분배, 진행 상태 기록, 에이전트 교체 |
| 구현자 | Claude (claude-opus-5-5, effort high) | 코드 구현, 테스트, 커밋 |
| 검수자 | Codex (gpt-6-sol) | 계획·설계 토론, 마일스톤 diff 리뷰 |

- 마일스톤 하나 = 구현 → 로컬 커밋 → 검수 → 수정 → push.
- 검수 지적 중 기술 판단이 갈리면 구현자와 검수자가 논의해 정하고, 큰 결정은 `Docs/Design/`에 기록한다.
- 기획 질문은 기본값으로 진행하고 [[결정 대기]]에 쓴다.
- 에이전트 맥락이 커지면 세션을 닫고 새로 띄운다. 이어받을 정보는 이 문서의 "진행 상태"와 "인계 메모"에 남긴다.

## 마일스톤

### M0. 저장소 뼈대와 초기 검증

- pnpm workspaces, strict TypeScript, Vitest, ESLint(import 방향 규칙: contracts → engine → 호스트).
- 패키지 골격: `packages/contracts`, `packages/engine`, `packages/agent-adapters`, `packages/cli`, `apps/desktop`(빈 셸). `plugin-sdk`, `mcp`는 MVP 이후라 만들지 않는다.
- [[기술 스택 결정]] §13 검증 중 엔진 바닥에 해당하는 것:
  - #1 named pipe 현재 사용자 전용 보안 설정
  - #5 worker 안 `node:sqlite` WAL과 동시 읽기
- 결과는 `Docs/Design/초기 검증 결과.md`에 기록한다.
- **완료 기준:** `pnpm install && pnpm -r build && pnpm -r test && pnpm lint`가 통과한다.

### M1. 계약, 이벤트 저장소, 명령 버스

- `contracts`: 명령·이벤트·봉투·노드 선언 타입과 JSON Schema(Ajv 2020-12, 원격 `$ref` 금지).
- 이벤트 로그(append-only, aggregate id/revision, 전역 sequence, 스키마 버전, 주체)와 같은 트랜잭션 안의 조회 테이블. 재생으로 조회 테이블 재구축.
- 명령 버스: 요청 id 멱등, 기대 revision, 호출자 맥락(주체·티켓·노드·실행 토큰).
- 가상 시계, 가짜 파일 시스템·프로세스 주입점.
- **완료 기준:** 명령 → 이벤트 → 조회 테이블, 크래시 후 재생 테스트 통과.

### M2. 워크플로 엔진

- 선언형 노드 타입(JSON)과 내장 실행기: 에이전트, 스크립트, 사람 승인, 합류.
- 노드 간 인계 봉투, 경로 표현식(`{{ input.x }}`, `{{ nodes.<id>... }}`)과 조건 JSON AST([[n8n 노드 데이터 전달 분석]] §6).
- 티켓: 템플릿 버전·해시 고정, 노드 상태(Wait/Running/Review/Done/Failed/Rejected/Paused/Queued. Stale은 상태값만 정의).
- 팬아웃·합류, 승인 게이트, QA 반려 루프.
- 기본 템플릿 "AI-Native SDLC"(BrainStorming → Spec → Plan → 병렬 Dev → QA → Done).
- 정의 파일 저장(JSON 정본, 임시 파일 → 교체 → DB 활성 등록 → 시작 시 복구).
- **완료 기준:** 가짜 어댑터로 기본 템플릿 티켓이 반려 1회를 거쳐 Done까지 가는 테스트.

### M3. 에이전트 어댑터, 엔진 데몬, `vuyro` CLI

- Claude(`stream-json`)와 Codex(`exec --json`) 어댑터: 메시지·도구 호출·사용량·세션 id·결과·정착 상태로 정규화. 모르는 이벤트는 원본 보존.
- §13 #3, #4: 가장 작은 모델로 실제 출력을 녹화해 픽스처로 쓰고 계약 테스트.
- 엔진 상주 프로세스: named pipe JSON-RPC, 이벤트 구독(sequence 이어받기), 단일 인스턴스 잠금.
- `vuyro` CLI: 티켓·노드 명령, `vuyro artifact add`, `vuyro node done`. 노드 에이전트는 환경 변수 실행 토큰으로 식별.
- 산출물 레지스트리(경로 + 버전). 노드별 시간·토큰(입력/캐시/출력)·도구 호출 집계(이벤트에서 계산).
- **완료 기준:** CLI로 티켓을 만들고 가짜 어댑터 에이전트가 `vuyro node done`으로 노드를 끝내는 통합 테스트.

### M4. 작업 공간과 내부 체크아웃

- 작업 공간 모드 `shared` / `worktree`(사용자 선택).
- 내부 체크아웃 장부(외부 툴 잠금 금지), 자동 체크아웃 훅(옵션): Claude `--settings` PreToolUse, Codex `hooks.PreToolUse`(§13 #2).
- 파일 변경 감지: 감시 + 읽기 전용 git 조회로 후보 → SHA-256. 귀속 불명 변경 표시.
- **완료 기준:** 두 노드가 같은 파일을 잡으려 할 때 충돌 정책대로 막히거나 대기하는 테스트.

### M5. 공유 노드

- 프로젝트 범위 노드, 대기열, 실행 조건, 실행 중 소스 보호, 실패 원인 티켓 추정, 원인 티켓 수정 전까지 멈춤, 결과를 티켓별로 나눠 돌려주기.
- **완료 기준:** 티켓 3개가 대기열에 들어와 한 번에 빌드되고, 실패 시 원인 티켓만 멈추는 테스트.

### M6. 데스크톱 앱

- Electron main(엔진 데몬 연결·기동, 트레이 상주, 완전 종료 확인), preload(contextIsolation), React + Vite UI.
- 화면: 칸반 보드, 그래프 캔버스(@xyflow/react), 노드 상세(시간·토큰·도구 호출, 로그), 승인/반려, 티켓 생성.
- 템플릿·노드 타입 JSON 가져오기/내보내기(봉투 형식, 비밀값 제외).
- UX 방향은 [[에이전트 패널 시안]](01 · 02 · 07).
- **완료 기준:** 앱에서 티켓을 만들고 승인 게이트를 통과시키는 흐름이 동작한다.

### M7. 데모

- 이 저장소 밖에 샘플 git 저장소(메모장 같은 작은 앱)를 만든다.
- 실제 Claude/Codex(가장 작은 모델)로 기본 템플릿 티켓 하나를 끝까지 돌리는 스모크.
- 데모 진행 문서와 [[결정 대기]] 정리.
